02 / Agent inspector

Read the request before the metadata.

OpenSessions separates task details from navigation. The corrected terminal adaptation gives state the left edge and the dim agent name the right edge when they fit, within a native fzf frame. A one-column inset and spaced sections appear when room permits. Request and command use normal foreground text; an amber command bar and compact dim provenance, title, location, and directory complete the structured inspector. Terminal output belongs in Terminal preview, selected with i.

Design reference with fictional lifecycle data. View actual attached terminal captures for runtime evidence. This browser illustration is not a screenshot of the terminal: CSS spacing, font metrics, backgrounds, and colors remain illustrative. A command is text to inspect, not an approval button.

Terminal adaptation scope: a native sharp-framed inspector, not a browser card, wrapping transcript, or approval control. Drawers of at least 16 available content rows space the sections; shorter drawers compact them. One-to-three-row drawers prioritize state and identity, then a verified request, then its command, within the fzf content budget. Long lines clip. The inspector ends after provenance, title, location, and directory: no Recent screen, screen divider, or captured agent TUI footer/status bar. Process-only agents retain a Detected card with lifecycle state unavailable and may still show explicitly unverified possible-request hints inferred from the visible screen. Ordinary panes retain a No agent / Terminal card with their actual command and location, without request inference. Fresh ordinary reports indicate no pending request reported; stale, unknown, or incomplete needs-input reports explain unavailable request details rather than inventing them. Stale reports omit old requests and do not infer new ones. Report age is not time spent waiting. Optional integrations supply lifecycle data when agents report it, not a layout change or manufactured request. Use i for Terminal preview and its terminal output; both modes retain the same frame and geometry, mode labels, and scrollbar without a scroll-position overlay. Close and reopen an existing sidebar after upgrading. Increasing @tmux-canopy-preview-height adds spacing; its default remains 35%. ASCII mode uses plain bars; monochrome mode omits color styling.
