# tmux Agent Sidebar Comparison

*Research date: 2026-10-05. Scope is limited to claims made in each project's
official GitHub repository README or linked first-party documentation.*

## At A Glance

| Tool | Pane, window, and session navigation | Sidebar or persistent UI | Agent awareness and alerts | Runtime trade-off |
| --- | --- | --- | --- | --- |
| [tmux-canopy](https://github.com/jonmosco/tmux-canopy) | Navigable sessions-to-windows-to-panes tree, global quick switcher, object creation/move/link/delete, and previews ([README](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#features); [reference](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#native-object-actions)). | Client-owned dock follows its client across windows/sessions; left/right split, popup, or adaptive mode ([reference](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#display-modes)). | Process detection plus optional lifecycle adapters for ten agent families; subagents, needs-input jump, desktop/tmux alerts, and activity/bell/silence notifications ([README](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#ai-agent-monitoring); [alerts](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#alerts)). | Bash/awk/fzf, one tmux snapshot per refresh, tmux-hook driven, and explicitly no daemon ([README](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#how-it-works)). |
| [tmux-sessionx](https://github.com/omerxx/tmux-sessionx) | Fuzzy session switch/create/delete/rename; optional windows list and session/window tree, with previews ([README](https://github.com/omerxx/tmux-sessionx/blob/main/README.md#working-with-sessionx-)). | On-demand `fzf-tmux` popup; its documented tree is a popup mode, not a persistent sidebar ([README](https://github.com/omerxx/tmux-sessionx/blob/main/README.md#configure-)). | The official README documents neither agent-state detection nor alerts ([README](https://github.com/omerxx/tmux-sessionx/blob/main/README.md)). | Small fzf/TPM plugin, but requires `fzf`, `fzf-tmux`, and `bat` (with optional zoxide) ([README](https://github.com/omerxx/tmux-sessionx/blob/main/README.md#prerequisites-️)). |

| [tmux-agent-sidebar](https://github.com/hiroppy/tmux-agent-sidebar) | One view tracks agent and shell panes across sessions/windows; also creates and tears down worktree, window, and branch together ([README](https://github.com/hiroppy/tmux-agent-sidebar/blob/main/README.md#features)). | Per-window or everywhere sidebar toggle ([README](https://github.com/hiroppy/tmux-agent-sidebar/blob/main/README.md#3-toggle-the-sidebar)). | Claude Code, Codex, and OpenCode metadata includes prompts, tool calls, waits, progress, and subagent trees; native desktop alerts cover finish, permission, and error ([README](https://github.com/hiroppy/tmux-agent-sidebar/blob/main/README.md#features)). | Prebuilt or source-built Rust binary; agent-specific hooks/plugins are required for detailed state ([README](https://github.com/hiroppy/tmux-agent-sidebar/blob/main/README.md#2-wire-up-the-agent-hooks)). |
| [jmux](https://github.com/jarredkenny/jmux) | Wraps real tmux, adds session switching, command palette, session/worktree creation, and agent control API ([README](https://github.com/jarredkenny/jmux/blob/main/README.md#agents-that-command-agents)). | Persistent rendered sidebar, toolbar, Command Center grid, and optional information/diff panels around tmux ([README](https://github.com/jarredkenny/jmux/blob/main/README.md#see-every-agent-at-a-glance)). | Hook-installed RUNNING/WAITING/COMPLETE state for Claude Code, Codex, and Pi; sidebar flags new output and agents needing review ([README](https://github.com/jarredkenny/jmux/blob/main/README.md#see-every-agent-at-a-glance)). | Self-contained binary drives tmux through interactive PTY plus control-mode channels; broader issue-tracker, code-host, and worktree workflow scope ([README](https://github.com/jarredkenny/jmux/blob/main/README.md#architecture)). |

## Current Positioning

Canopy's clear differentiation is a **tmux-native workspace navigator and
multi-agent monitor in one UI**: it retains ordinary tmux sessions and layouts,
models every session/window/pane rather than only agent sessions, and adds
provider-neutral terminal notifications alongside verified lifecycle state
([README](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#features);
[reference](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#notifications)).
Its no-daemon, one-snapshot, hook-driven design is a meaningful operational
contrast with opensessions' local server/watchers and herdr's persistent
runtime/server ([Canopy architecture](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#snapshot-rendering-and-stable-selection);
[opensessions architecture](https://github.com/Ataraxy-Labs/opensessions/blob/main/README.md#repo-layout);
[herdr README](https://github.com/herdrdev/herdr/blob/master/README.md)).

## Gaps And Boundaries

- Canopy has no combined multi-machine view, remote reconnection, or agent-control socket API, which herdr explicitly provides ([Canopy limitations](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#current-limitations); [herdr README](https://github.com/herdrdev/herdr/blob/master/README.md)).
- It does not provide jmux's ticket-to-worktree-to-agent workflow, tracker/code-host integrations, or integrated diff review ([jmux README](https://github.com/jarredkenny/jmux/blob/main/README.md#from-ticket-to-merged-without-leaving-the-terminal)).
- Unlike the Rust sidebars, Canopy's detailed lifecycle state is optional and adapter-dependent; process-only detection cannot establish needs-input state ([Canopy reference](https://github.com/jonmosco/tmux-canopy/blob/main/docs/reference.md#agent-lifecycle-adapters)).
- Canopy deliberately does not run a permanent server, so it does not expose the HTTP metadata API offered by opensessions ([Canopy architecture](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#how-it-works); [opensessions API](https://github.com/Ataraxy-Labs/opensessions/blob/main/README.md#programmatic-api)).
- Its stable-slot model is optimized for one active sidebar owner per tmux server, a documented constraint for simultaneously attached clients ([Canopy limitations](https://github.com/jonmosco/tmux-canopy/blob/main/README.md#current-limitations)).
